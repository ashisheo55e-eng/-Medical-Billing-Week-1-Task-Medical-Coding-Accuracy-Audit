**1. Executive Summary**

This report presents a structured medical coding accuracy audit using five hypothetical patient records. The purpose is to demonstrate a consistent method for reviewing clinical documentation, identifying the condition chiefly addressed, locating the appropriate diagnosis code, considering relevant procedure or service codes, and checking the final code set for completeness and compliance. The cases cover type 2 diabetes mellitus, essential hypertension, community-acquired pneumonia, urinary tract infection, and acute appendicitis. They are fictional educational examples and do not represent actual patients or claims.

The audit emphasizes that a code must be supported by the provider’s documentation and the applicable code-set instructions. A coder should not diagnose a patient, infer a complication from a laboratory value, or select a procedure code merely because a service seems likely. Diagnosis coding, CPT reporting, and HCPCS Level II reporting serve different purposes and must be evaluated separately. For every case, the report records the documented facts, proposed codes, rationale, potential errors, and a recommended correction or validation step.

The review uses the FY 2027 ICD-10-CM Official Guidelines for Coding and Reporting, effective October 1, 2026 through September 30, 2027, as the current diagnosis-coding guideline reference at the time this report is prepared. CPT code examples are educational and must be confirmed in the current licensed CPT code set, payer policy, and applicable edits before real claim submission.

**2. Introduction and Objectives**

Medical coding converts documented healthcare diagnoses, services, and supplies into standardized alphanumeric codes. Accurate coding supports claim processing, reimbursement, clinical data reporting, quality measurement, and communication among providers, payers, and healthcare organizations. Inaccurate coding can cause claim denials, incorrect reimbursement, compliance exposure, distorted patient records, and avoidable rework.

A medical coding accuracy audit is a systematic review of a sample of records to determine whether reported codes are complete, accurate, properly sequenced, and supported by the medical record. The audit should assess both undercoding and overcoding. Undercoding may omit a documented condition or service; overcoding may report a condition, level of specificity, or service that the record does not support.

The objectives of this assignment are to: 
(1) demonstrate a repeatable record-review process; 
(2) assign appropriate ICD-10-CM diagnosis codes based on documented diagnoses; 
(3) identify relevant CPT and HCPCS Level II examples when the documentation supports them; 
(4) explain the rationale for each assignment; 
(5) recognize discrepancies and propose corrections; 
(6) describe how coding updates and compliance checks should be maintained.

**3. Scope, Assumptions, and Limitations**

The five cases in this report are simulated outpatient examples created for training. The cases intentionally provide only selected clinical facts, not a complete medical record. Therefore, code assignments are conditional on the documentation as written. In actual coding, the entire encounter record, provider-authenticated assessment, orders, results, procedure report, place of service, date of service, payer requirements, and current code-set instructions must be reviewed.

The examples focus on ICD-10-CM diagnosis coding and selected CPT/HCPCS Level II services. They do not attempt to assign every possible code for every service. An E/M code, for example, cannot be selected solely from a diagnosis or a short clinical summary. It requires review of the applicable medical decision-making or time rules and all required documentation. Likewise, a drug HCPCS code requires the exact drug, dosage, unit definition, route, and payer-specific billing rules.

This is an educational audit, not a legal opinion, payer coverage determination, or substitute for an official codebook. Before using any code on a live claim, the coder must verify it in the current-year Alphabetic Index and Tabular List, official guidelines, CPT/HCPCS resources, payer policy, and applicable edits.

**4. Medical Coding Audit Methodology**

**1. Record selection and preparation**
A sample should be selected using a defined audit objective. For a small training exercise, five records can provide a useful demonstration of different coding concepts. In a production audit, the sample should be large and representative enough for the risk being measured. The auditor records the encounter type, date of service, provider documentation available, codes initially assigned, and any relevant claim details. Patient identifiers should be removed from training materials and protected in operational audits.

**2. Review the complete documentation**
The auditor reads the complete record rather than relying only on a problem list, billing note, or isolated test result. The review includes the chief complaint, history, examination, assessment, plan, orders, diagnostic reports, medication administration record, and procedure documentation where relevant. The final provider assessment is especially important because symptoms and abnormal findings do not automatically establish a definitive diagnosis.

**3. Identify the reportable condition**
For an outpatient encounter, the first-listed diagnosis is generally the condition, problem, or other reason shown in the documentation to be chiefly responsible for the services provided, subject to the official guidelines and code-specific instructions. Additional diagnoses may be reported when they are documented and meet reporting criteria. A coder must not code uncertain outpatient diagnoses as if they were confirmed; symptoms, signs, or abnormal test results may be reported when appropriate.

**4. Locate and validate diagnosis codes**
The coder begins with the ICD-10-CM Alphabetic Index and then verifies the candidate code in the Tabular List. The Tabular List must be checked for inclusion terms, Excludes1 or Excludes2 notes, “code first” instructions, “use additional code” instructions, laterality, required characters, and billable specificity. The coder also confirms that the code is valid for the date of service and applicable fiscal year.

**5. Review procedure and service codes**
CPT codes describe many professional services and procedures, while HCPCS Level II codes commonly describe certain drugs, supplies, equipment, and services not represented by CPT. A service should be reported only when documentation supports that it was performed, ordered, supplied, or administered as required. The auditor checks the code descriptor, units, modifiers, place of service, bundling rules, and payer requirements. For Medicare claims, current National Correct Coding Initiative (NCCI) edits should be reviewed where applicable.

**6. Perform an independent accuracy check**
The auditor compares each proposed code with the provider’s words and the code-set instructions. The check asks: Is the diagnosis actually documented? Is the specificity supported? Is the code valid on the date of service? Is the service documented as performed? Are units and modifiers correct? Is a more specific code available? Are any mutually exclusive or bundled services reported separately without justification? If documentation is unclear or contradictory, the coder should follow the organization’s query process rather than assume the answer.

**7. Record findings and corrective action**
Each discrepancy is classified, for example, as unsupported diagnosis, missing specificity, incorrect code selection, omitted code, sequencing issue, incorrect units, unsupported procedure, or failure to apply an edit. The auditor records the evidence, the corrected coding recommendation, the reason, the responsible workflow step, and whether education or a process change is needed. Findings should be trended so recurring errors can be prevented.

**5. Simulated Patient Records and Coding Outcomes**

The following cases are deliberately concise. Diagnosis code selections are based on the diagnoses explicitly stated in each scenario. CPT/HCPCS examples are conditional and must be validated against the complete documentation and current code references.

**Case 1 – Type 2 Diabetes Mellitus without documented complication**
Simulated documentation: A 52-year-old patient attends an established outpatient visit for follow-up of type 2 diabetes. The provider documents “Type 2 diabetes mellitus without complications.” The patient’s glucose is reviewed and the plan includes continuation of the current oral medication and routine follow-up. No diabetic kidney, eye, neurological, circulatory, or other complication is documented.

|  Code set  |  Proposed code  |  Description / use | 
|------------|-----------------|--------------------|
| ICD-10-CM  | E11.9 | 	Type 2 diabetes mellitus without complications | 
| CPT (conditional) | 99213 | Established-patient office/outpatient E/M; only if the documented MDM or time supports this level | 

Coding rationale: E11.9 is supported because the provider explicitly documents type 2 diabetes without a complication. An elevated glucose value alone does not authorize the coder to infer a specific diabetic complication. If the record documents hyperglycemia as a provider-assessed diagnosis, the coder must evaluate the appropriate code and current Index/Tabular instructions rather than automatically using E11.9. The E/M example is not determined by the diagnosis; the complete note must support the selected level under current E/M rules.

Audit observation: Potential error: assigning a complication code such as diabetic nephropathy or diabetic neuropathy based only on a laboratory value, medication, or historical problem list. Another error is selecting an E/M level based only on the number of diagnoses.

Correction / prevention: Compare the final assessment with the code descriptor. Confirm whether complications are actually diagnosed and addressed. Validate the E/M level using documented medical decision-making or time and applicable payer rules. Query the provider if the assessment is contradictory or incomplete.

**Case 2 – Essential (primary) hypertension**
Simulated documentation: A 60-year-old patient presents for an outpatient follow-up. The provider documents essential hypertension. Blood pressure at the visit is 160/100 mmHg. The plan includes medication adjustment, home blood-pressure monitoring, and follow-up. No hypertensive heart disease, chronic kidney disease, or other related condition is diagnosed in the assessment.

|  Code set  |  Proposed code  |  Description / use | 
|------------|-----------------|--------------------|
| ICD-10-CM |  I10  | Essential (primary) hypertension | 
| CPT (conditional) | 	99214  | Established-patient office/outpatient E/M; report only when the note supports this level |   

Coding rationale: I10 is appropriate for the documented diagnosis of essential hypertension when no more specific hypertensive condition is established. A high blood-pressure reading is a clinical measurement; it does not independently establish hypertensive heart or kidney disease. If the provider documents a related condition, the coder must apply the relevant combination-code and sequencing instructions.

Audit observation: Potential error: reporting hypertensive chronic kidney disease or hypertensive heart disease without provider documentation. A further error is assuming that a blood pressure of 160/100 automatically determines the E/M level.

Correction / prevention: Verify the assessment and plan, check for documented associated conditions, and use the Index and Tabular List to confirm any additional code requirements. For E/M, review the entire encounter and the current office/outpatient E/M guidelines.

**Case 3 – Community-acquired pneumonia, organism unspecified**

Simulated documentation: A 45-year-old patient is evaluated for fever, cough, and shortness of breath. Chest imaging is interpreted as showing pneumonia. The provider’s final diagnosis is community-acquired pneumonia, organism not identified. A two-view chest X-ray is documented as performed. No specific bacterial or viral organism is identified in the record.

|  Code set  |  Proposed code  |  Description / use | 
|------------|-----------------|--------------------|
| ICD-10-CM | J18.9 | Pneumonia, unspecified organism | 
| CPT (conditional) | 71046  | Radiologic examination, chest; 2 views |  
| CPT (conditional  | 99214  | 	Office/outpatient E/M only if the documentation and setting support this code | 

Coding rationale: J18.9 is supported by the final provider diagnosis of pneumonia with no organism specified. A coder must not assume a bacterial organism or assign a more specific organism code without documentation. CPT 71046 may be appropriate when the report supports a two-view chest radiographic examination. The imaging code should be checked against the actual number of views, professional/technical billing arrangement, and payer rules.

Audit observation: Potential error: choosing a bacterial pneumonia code because antibiotics were prescribed. Medication choice does not prove the causative organism. Another error is reporting a chest imaging code with the wrong number of views or reporting a service not documented as performed.

Correction / prevention: Use the final diagnostic statement and imaging report. Confirm the exact imaging service and number of views. Do not infer the organism from treatment. Review whether the E/M service is separately reportable and whether applicable bundling or payer rules affect billing.

**Case 4 – Urinary tract infection, site not specified**

Simulated documentation: A 29-year-old patient reports dysuria and urinary frequency. Urinalysis is performed. The provider documents urinary tract infection, site not specified, and prescribes treatment. The documentation does not identify cystitis, pyelonephritis, or a specific organism. A urine culture is ordered and collected

|  Code set  |  Proposed code  |  Description / use | 
|------------|-----------------|--------------------|
| ICD-10-CM | N39.0 | Urinary tract infection, site not specified | 
| CPT (conditional) | 81002  | Urinalysis by dip stick or tablet reagent, non-automated, without microscopy; only if this exact method is documented |  
| CPT (conditional  | 	87086 | 	Culture, bacterial; quantitative colony count, urine | 

Coding rationale: N39.0 reflects the provider’s documented UTI when the site is not specified. The coder should not convert the diagnosis to cystitis or pyelonephritis based only on symptoms. CPT 81002 is conditional on the actual urinalysis method; an automated or microscopic test may require a different code. CPT 87086 is an example for a urine bacterial culture and must be checked against the actual laboratory service and reporting rules.

Audit observation: Potential error: coding a specific UTI site that is not documented, or selecting a urinalysis code without checking whether the test was automated, non-automated, or included microscopy. Another risk is reporting a culture that was ordered but not actually collected or performed.

Correction / prevention: Match the code to the documented test method and completed service. Review the laboratory order and result. If the provider’s diagnosis is unclear, do not infer a site from symptoms; follow the provider-query process where clarification is necessary.

**Case 5 – Acute appendicitis without documented perforation or gangrene**

Simulated documentation: A 34-year-old patient is admitted with right lower abdominal pain. Imaging and the surgeon’s assessment support acute appendicitis. The operative report documents laparoscopic appendectomy. The final diagnosis states acute appendicitis without perforation or gangrene. No localized peritonitis is documented in the summary.

|  Code set  |  Proposed code  |  Description / use | 
|------------|-----------------|--------------------|
| ICD-10-CM | K35.80 | 	Unspecified acute appendicitis without perforation or gangrene | 
| CPT (conditional) | 	99214  | Laparoscopy, surgical, appendectomy | 

Coding rationale: K35.80 is presented as the diagnosis-code candidate because the scenario documents acute appendicitis without perforation or gangrene and does not establish localized peritonitis. The coder must verify the exact code in the current FY 2027 Tabular List and confirm the operative and final diagnosis documentation. CPT 44970 is the laparoscopic appendectomy example; the operative report must support the approach and procedure actually performed.

Audit observation: Potential error: selecting a code that includes perforation, gangrene, or localized peritonitis when those details are absent. Another error is reporting an open appendectomy code when the operative report documents a laparoscopic procedure, or vice versa.

Correction / prevention: Read the final diagnosis and complete operative report. Confirm the surgical approach, procedure performed, and any documented complications. Do not infer perforation from the severity of pain or imaging alone. Check code-specific notes and payer edits before claim submission.

**7. Common Discrepancies and Error-Correction Plan**

The simulated audit highlights recurring risks that can occur in routine coding workflows. The first is unsupported specificity. A coder may be tempted to choose a more detailed diagnosis based on symptoms, medication, laboratory values, or assumptions about typical disease patterns. The correct approach is to code what the provider has documented, apply official conventions, and request clarification when the record is insufficient.

The second risk is incomplete code validation. Selecting a code from memory or from an internet search without checking the current Tabular List can lead to an invalid, incomplete, or non-specific code. Every candidate should be verified for code validity, required characters, instructional notes, exclusions, and date-of-service applicability.

The third risk is confusing diagnosis codes with service codes. ICD-10-CM describes diagnoses and reasons for encounters. CPT describes many procedures and professional services. HCPCS Level II describes selected drugs, supplies, equipment, and other services. A diagnosis does not prove that a procedure occurred, and an order does not always prove that a service was completed. The record must support each reported item.

The fourth risk is incorrect E/M level selection. E/M coding must follow the applicable current rules for the setting and code family. The diagnosis count, patient age, or apparent seriousness of the condition alone does not determine the level. The auditor should review the documented medical decision-making or time, as applicable, and ensure the correct setting and patient status.

The fifth risk is failure to review edits and payer requirements. NCCI procedure-to-procedure edits are designed to prevent inappropriate payment for code pairs that generally should not be reported together, while medically unlikely edits address units of service. An edit should be reviewed in context; a modifier should never be added merely to bypass an edit. The documentation must support the distinct service and the modifier’s use.

A practical correction workflow is: identify the affected claim or record; compare the assigned code with the source documentation; verify the code in the current official code set; determine whether the issue is a documentation gap, code-selection error, sequencing issue, or billing edit; correct the code or request a compliant provider clarification; document the audit trail; and provide targeted feedback. If a claim has already been submitted, follow the organization’s correction, replacement, or appeal process and payer rules.

**8. Guideline Updates, Compliance, and Quality Control**

ICD-10-CM is updated on a fiscal-year basis. For this report, FY 2027 applies to encounters from October 1, 2026 through September 30, 2027. CMS makes the current code files and official guidelines available through its ICD-10 resources page. Coders should confirm the correct code-set year using the date of service rather than relying on a code list saved from a prior year.

CPT and HCPCS Level II resources also require regular review. CPT is maintained by the American Medical Association, while HCPCS Level II updates are published by CMS. A coding team should maintain access to current authorized code references and review annual and quarterly updates, payer bulletins, coverage policies, and edit files. This report does not reproduce the full CPT or HCPCS code sets.

For Medicare claims, CMS publishes NCCI procedure-to-procedure edits and medically unlikely edits, with quarterly updates. The auditor should use the edit files applicable to the date of service and setting. NCCI edits are not a substitute for reading the CPT code descriptors and guidelines; they are an additional compliance check. Commercial payers may apply their own policies and may not follow every Medicare rule in exactly the same way.

A sustainable update process includes assigning responsibility for monitoring official releases, maintaining a change log, identifying affected code families and workflows, updating encoder or billing software, educating coders, and conducting post-update sample audits. Staff should document the source and effective date of any coding guidance used. When a code or guideline changes, older training examples should be reviewed before reuse.

Compliance also requires confidentiality, secure handling of records, accurate documentation, and no alteration of clinical facts to obtain payment. Coders should never create diagnoses, change provider wording, unbundle services improperly, or select codes solely to maximize reimbursement. Queries must be non-leading, clinically reasonable, and consistent with organizational policy.

**9. Recommendations for Improving Coding Accuracy**

1.Use a standardized audit checklist for every record: patient/encounter details, provider diagnosis, specificity, code validity, sequencing, services performed, units, modifiers, and payer edits.

2.Require Index-to-Tabular verification for diagnosis codes rather than relying on memory or search-engine snippets.

3.Separate diagnosis review from procedure and supply review so each code is supported by its own documentation.

4.Provide focused education on common errors, including unspecified versus specific diagnoses, combination codes, Excludes notes, E/M selection, and laboratory test variations.

5.Use provider queries only when documentation is clinically unclear, conflicting, or incomplete and clarification is necessary for accurate coding.

6.Track error categories and calculate an accuracy rate using a consistent denominator. Share trends with coders and supervisors without discouraging appropriate questions.

7.Review high-risk and frequently denied claims more often, including those involving complex procedures, drugs, modifiers, units, and medical necessity.

8.Maintain current-year official code references and a documented process for annual and quarterly updates.

9.Perform periodic second-level reviews and compare audit findings over time to confirm whether education and workflow changes are effective.

10.Protect patient privacy by using de-identified training cases and approved systems for real records.

**10. Conclusion**

This medical coding accuracy audit demonstrates that reliable coding depends on careful documentation review, correct use of official code references, and a disciplined validation process. Across the five simulated cases, the key diagnosis candidates were E11.9 for type 2 diabetes without complications, I10 for essential hypertension, J18.9 for pneumonia with unspecified organism, N39.0 for UTI with unspecified site, and K35.80 for acute appendicitis without perforation or gangrene. The procedure and service examples were conditional on the exact services documented and must be checked against current CPT/HCPCS resources and payer rules.

The most important lesson is that coders must not make clinical assumptions. A laboratory value does not independently establish a complication, a medication does not prove an organism, and an order does not prove that a service was performed. Code specificity must come from the documentation and the official classification. Procedure codes must match the service actually provided, including approach, method, units, and any applicable modifiers.

A strong audit process does more than find mistakes. It identifies why errors occur, supports accurate corrections, educates the coding team, and creates controls to reduce recurrence. By using current guidelines, checking code-set updates, reviewing applicable edits, and escalating unclear documentation appropriately, a medical coder can contribute to compliant claims, reliable health information, and better revenue-cycle performance.
